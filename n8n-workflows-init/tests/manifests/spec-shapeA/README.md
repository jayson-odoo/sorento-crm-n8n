### Transport note (worth reading before the promote)

The MCP `setNodeParameter` route was attempted twice and **failed the byte-gate both times**: the
tool-call authoring channel normalises `\uXXXX` sequences into the literal characters, so the
deployed body came back carrying real dash glyphs (`‐-―−﹘﹣－`) where the tested artifact has ASCII
escapes. Functionally the same regex; not the same bytes, and not ASCII. Neither draft was
published. The write that landed is a **file-driven REST GET → replace one leaf → PUT**, which is
what LESSONS §71's transport corollary prescribes for exactly this reason. Use the same route for
the live promote, and keep the byte-gate — it is the only thing that caught this.
